# Agent Live Activity — activation runbook

This directory is the **iOS Live Activity (ActivityKit) scaffold**. It currently
**ships dark**: the JS service (`src/services/live-activities.ts`) is wired and
tested, but the native widget-extension target is **not yet compiled into the
app**, and the feature flag is **OFF**. Nothing here affects the current
TestFlight build.

## Why it's safe to merge now

- `live-activities.ts` looks up the native module via `requireOptionalNativeModule`,
  which returns `null` (never throws) when the target isn't built. Every function
  guards on `flag && nativeModule && OS-allows`, so a dark build is a guaranteed
  no-op. Covered by `live-activities.test.ts`.
- The Swift files live **outside `ios/`** (which is gitignored + regenerated by
  `expo prebuild`), so prebuild can't wipe them.

## Activation (requires a dev-client cycle on a real device — do NOT skip)

Live Activities **cannot** run in Expo Go and add a **new code-signed app
extension** to the archive, so they need one prove-out cycle before shipping:

1. **Install the target plugin** (one-time):
   ```bash
   cd apps/mobile
   npx expo install @bacons/apple-targets
   ```
2. **Wire app.json** (do these together):
   - Add `"@bacons/apple-targets"` to the `plugins` array.
   - Add to `ios.infoPlist`: `"NSSupportsLiveActivities": true`.
   - Add the app-group entitlement to the **main app** so it matches
     `expo-target.config.js` (`group.com.binarybros.clawket`).
   - Add an `appExtensions` entry under
     `extra.eas.build.experimental.ios.appExtensions` for the widget bundle id
     `com.binarybros.clawket.AgentActivity` (mirror the existing sharing-extension
     entry) so EAS/Xcode provisions it.
   - Ensure `AgentActivityAttributes.swift` is a member of **both** the app
     target (for the module) and the widget target; `ClawketLiveActivityModule.swift`
     is app-target only; `AgentActivityWidget.swift` is widget-target only.
3. **Apple Developer portal**: enable the **App Groups** capability on App ID
   `com.binarybros.clawket`, create/register the widget App ID
   `com.binarybros.clawket.AgentActivity`, and refresh provisioning profiles.
4. **Prebuild + dev-client build on a physical device** (iPhone, iOS ≥ 16.2):
   ```bash
   npx expo prebuild -p ios --clean
   # build a dev client / run on device via Xcode or eas build --profile development
   ```
   The prebuild audit (2026-06-11) confirmed `--clean` safely regenerates the
   sharing extension, all 6 localizations, usage strings, `.xcode.env`, and the
   build number from `app.json` — so this won't lose existing customizations.
5. **Test on device** with the flag ON:
   ```bash
   EXPO_PUBLIC_LIVE_ACTIVITIES_ENABLED=1
   ```
   Call `startAgentActivity({ title, status, progress })`, then `updateAgentActivity`
   / `endAgentActivity`. Confirm the Lock Screen card + Dynamic Island render and
   the elapsed timer ticks (OS-driven from `startedAtMs`).
6. **Ship dark first**: archive to TestFlight with the flag **OFF** to prove the
   new extension archives + signs cleanly (this is the only archive-time risk —
   provisioning the new target). Then flip `EXPO_PUBLIC_LIVE_ACTIVITIES_ENABLED=1`
   in a later build once confident.

## Files

| File | Target membership | Role |
|------|-------------------|------|
| `AgentActivityAttributes.swift` | app **and** widget | shared ActivityKit data shape |
| `AgentActivityWidget.swift` | widget only | SwiftUI Lock Screen + Dynamic Island UI |
| `ClawketLiveActivityModule.swift` | app only | Expo module `ClawketLiveActivity` (start/update/end) |
| `expo-target.config.js` | — | `@bacons/apple-targets` widget target declaration |

JS entry point: `src/services/live-activities.ts` (flag: `EXPO_PUBLIC_LIVE_ACTIVITIES_ENABLED`).
